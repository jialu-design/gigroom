# GigRoom 声场

> 面向中国独立音乐现场的轻量观演工具。

**让去现场这件事简单一点。**

## Why GigRoom

看一场独立音乐演出，经常需要在多个地方切换：票务平台买票、小红书找搭子、闲鱼出收票、微信群获取现场信息。

很多需求其实非常短暂：拼双人票、找搭子、临时收出票、散场拼车。为了这些需求加入大量微信群、添加陌生好友，会带来额外的社交和信息负担。

GigRoom 围绕具体 Show，把这些观演需求集中在一个轻量空间里。

**需要的时候找到彼此，解决需求，然后各自离开。**

## Product

核心结构：**Artist → Show → 观演小屋**

V1 已实现：

- **Artist / 演出发现**：按城市、风格浏览乐队与演出，关注乐队
- **Show Detail**：阵容、时间场地、票价、演出状态与叙事化内容编排
- **感兴趣 / 我要去 / 看过**：单状态互斥，沉淀个人观演轨迹
- **第三方票务入口**：跳转售票平台完成购票
- **观演小屋**：加入某场演出后进入的临时空间，演出结束后保留历史
- **讨论**：演出相关的讨论串与回复
- **找搭子**：按需求标签（一起看演出、排队、拼车、拼双人票、互拍等）发帖与回复
- **出收票**：同场出票 / 收票、票面价校验、收藏、站内私聊沟通
- **Live 现场分享**：演出当天起发布照片、文字与外部视频链接，演出后成为现场记录
- **通知**：回复、互动、演出提醒等站内通知
- **个人观演记录**：关注的乐队、感兴趣 / 要去 / 看过的演出、加入过的小屋与自己的帖子

## Product Principles

### Show First

所有核心行为围绕具体 Show 发生。

### Need-driven

找搭子、拼票、出收票等连接来自具体观演需求。

### Lightweight

降低临时观演需求带来的社交和信息负担。

## V1.1 / What's Next

- **即时观演需求**：找搭子 / 拼票 / 拼车等需求状态与更强时效性
- **Live Archive**：照片 + 一句话形成个人现场档案和年度回顾
- **Artist 档案**：风格介绍、历史 Show、现场内容沉淀
- **Artist / Host 创建和认领 Show**

V1.1 继续保持 Show-centric、即时需求、轻量连接、现场记忆。

- zustand（客户端状态与本地持久化）
- Vitest（单元 / 行为测试）
